# Testing Standards

## Overview

Test the game logic hard, the UI pragmatically. Pure rules (grading, mistake
budget, win/lose, share-grid generation) get thorough unit tests; the assembled
experience gets a few end-to-end smoke tests in a real browser.

## Testing Framework

**Framework**: Vitest (unit) + Playwright (e2e)
**Runner**: Vitest runner; Playwright test runner

## Test Types

| Type | Tool | Location | When to Use |
|------|------|----------|-------------|
| Unit | Vitest | `tests/unit/` | Pure logic in `src/lib/` (grading, state, loaders, share grid) |
| Component | Vitest + happy-dom/@open-wc | `tests/component/` | Lit component rendering and interaction |
| E2E | Playwright | `tests/e2e/` | Full play-through of a daily puzzle in a browser |

## Coverage Requirements

**Target**: 90% on `src/lib/` (game logic); overall pragmatic
**Enforcement**: CI reports coverage; lib thresholds enforced

**Critical paths that MUST have coverage:**
- Grading a submission (correct / wrong counts)
- Mistake-budget enforcement (win at 0 wrong, lose past the limit)
- Puzzle JSON loading and shape validation
- Share-grid (emoji result) generation
- Streak read/write in `localStorage`

## Test Naming

**Pattern**: `describe('<unit>') > it('does X when Y')`

**Examples**:
- `gradeSubmission > marks solved when all actors correct` — happy path
- `gradeSubmission > flags lost when wrong exceeds maxMistakes` — boundary

## Test Structure

```javascript
import { describe, it, expect } from 'vitest';
import { gradeSubmission } from '../../src/lib/grading.js';

describe('gradeSubmission', () => {
  it('marks solved when all actors correct', () => {
    const key = { a: 'film1', b: 'film2' };
    expect(gradeSubmission({ a: 'film1', b: 'film2' }, key, 4).solved).toBe(true);
  });
});
```

## Mock Strategy

**Approach**: Avoid mocks in lib tests (pure functions). For component/e2e, use static fixture puzzle JSON instead of live TMDB.

**Guidelines**:
- Never call the live TMDB API in tests
- Use fixed fixture puzzles checked into `tests/fixtures/`
- Stub `localStorage` via jsdom/happy-dom or Playwright context

## Test Data

**Strategy**: Checked-in fixture puzzle JSON mirroring the production schema

**Guidelines**:
- Keep at least one canonical 8-actor / 2-film fixture
- Include an edge fixture (unbalanced casts, shared actor) for grading tests

## Running Tests

```bash
# Run all tests
npm test

# Run with coverage
npm run test:coverage

# Run specific test file
npx vitest tests/unit/grading.test.js

# Run in watch mode
npx vitest --watch
```
