# Coding Standards

## Overview

Web-platform-first JavaScript. Favor native browser APIs and standards over
abstractions. Lit Web Components provide structure and reactivity; everything
else is plain ES modules, modern CSS, and HTML. Keep the dependency surface
small and the code legible.

## Code Formatting

**Tool**: Prettier

**Enforcement**: Format on save + CI check

### Key Settings

- **Semicolons**: yes

## File Organization

### Project Structure

```
/
├── index.html
├── src/
│   ├── components/      # Lit Web Components (<call-sheet-*>)
│   ├── lib/             # framework-free logic (grading, state, loaders)
│   ├── styles/          # CSS (tokens, globals)
│   └── main.js          # entry point
├── public/
│   └── puzzles/         # static per-day puzzle JSON
├── scripts/
│   └── build-puzzles.js # offline TMDB curation -> puzzle JSON
└── tests/               # vitest unit + playwright e2e
```

### Conventions

- **Logic vs view**: keep game rules (grading, mistake budget) in `src/lib/` as pure, testable functions — components stay thin
- **No secrets client-side**: TMDB key only in `scripts/` (build time)
- **Custom elements**: one component per file, tag prefix `call-sheet-`

## Import Order

```javascript
// 1. Third-party (lit)
import { LitElement, html, css } from 'lit';
// 2. Local lib
import { gradeSubmission } from '../lib/grading.js';
// 3. Local components
import './call-sheet-actor.js';
```

**Rules**:
- Use native ES module imports with explicit `.js` extensions
- Group third-party, then local lib, then local components
- No bare deep imports into node internals

## Error Handling

### Pattern

**Approach**: Fail gracefully in the UI; throw in pure logic and catch at the component boundary

### Guidelines

- Network/JSON load failures show a user-facing fallback ("Couldn't load today's puzzle")
- Validate puzzle JSON shape on load; never assume fields exist
- Build script exits non-zero on TMDB/curation errors

### Example

```javascript
try {
  const puzzle = await loadPuzzle(dateKey);
  this.render(puzzle);
} catch (err) {
  this.showError("Couldn't load today's puzzle. Try again later.");
  console.error(err);
}
```

## Logging

**Tool**: `console` (browser) / `console` (build script)
**Format**: Plain, contextual messages

### Log Levels

| Level | Usage |
|-------|-------|
| error | Failures that break the experience |
| warn | Recoverable issues (malformed optional data) |
| info | Build-script progress |

### Guidelines

**Always log**:
- Build-script curation steps and counts
- Client load failures (to console)

**Never log**:
- TMDB API key or any secret
- Full puzzle answers in production client logs

## Code Patterns

### Preferred Patterns

#### Pure game logic

Grading, mistake counting, and win/lose are pure functions in `src/lib/` — easy to unit test, framework-agnostic.

```javascript
export function gradeSubmission(assignment, answerKey, maxMistakes) {
  const wrong = Object.entries(assignment)
    .filter(([actor, film]) => answerKey[actor] !== film).length;
  return { wrong, solved: wrong === 0, lost: wrong > maxMistakes };
}
```

### Anti-Patterns to Avoid

- **Heavy framework creep**: don't reach for large libraries; prefer platform APIs
- **Logic in components**: keep rules out of the view layer
- **Shipping secrets**: never reference the TMDB key from client code
